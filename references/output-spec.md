## 各章节要求

| 章节 | 要求 |
|---|---|
| front matter | 纯数字，不要写「约」。`modules` 不含 M99 |
| 错题本变化信息 | 必须紧跟 front matter，见下节 |
| 目录 | 带锚点链接与题号区间，方便跳转。M99 即使 0 题也列出 |
| 模块章节 | 一级标题用 `##`，内部固定两小节：`### 知识点` 在前，`### 错题` 在后 |
| 通用方法索引 | 只收解析里明确写出、且在 **≥2 道题**中出现的方法。不足 2 题的留在该题的「方法沉淀」里，不进索引。没有就整节写「本期无」 |
| M99 待归类 | 没有就写「本期无」。不许省略章节——省略了下期会找不到位置 |
| 重复项清单 | 没有就写「本期无」 |
| 待人工确认 | 没有就写「本期无」 |
| 解析缺失清单 | 没有就写「本期无」 |
| 整理说明 | 必须写数量守恒算式，让用户能一眼核对 |

末尾四个清单即使为空也要保留章节，这是文件结构的一部分，缺了会让后续追加找不到挂载点。

追加：

```markdown
## 错题本变化信息
```

## 统计口径

错因分布**只统计已勾选（☑）的项**。生成时 AI 不勾任何一项，所以首次生成必然是：

```markdown
- 错因分布：待标注（11 题）
```

用户标注后再追加时，重算并写成：

```markdown
- 错因分布：概念不清 4 / 审题偏差 2 / 计算失误 1 / 未标注 4
```

不要为了统计好看去猜错因。宁可整列显示「待标注」。
