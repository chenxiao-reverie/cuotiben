# 错题本 · cuotiben

> 把带解析的错题和零散知识点摘录，重建成一份可长期追加、结构稳定的 Markdown 错题本知识库。
>
> **你负责做题和贴解析，它负责把解析变成能反复翻的东西。**

## 它解决什么问题

错题本的真实难点从来不是「记下来」，而是**三个月后还找得到、还看得懂、还能接着往下加**。

手写和随手记的错题本通常死在同一个地方：题号越加越乱、模块越堆越糊、同一道题重复记三遍、解析抄了八百字但复习时只想看那两句关键判断。

这个 Skill 把「整理」这件事拆成一套有约束的流水线：编号只增不改、模块可检索、解析只压缩不重写、错因留给你自己勾。

| 手工整理 | 本 Skill |
|---|---|
| 题号随手写，追加几次就乱了 | `Q-01…` 一经生成永不改号，新增只往后接 |
| 模块叫「第一章」「其他」「综合」 | 模块名必须是能当检索词用的考点名词短语 |
| 同一道题在多处重复出现 | 相似题自动合并，重复项清单留痕可查 |
| 解析整段照抄，越抄越厚 | 压缩到 ≤5 步，只留推导环节，删解释性废话 |
| 复习时不知道错在哪 | 7 项固定错因 + 依据，勾选权在你手里 |
| 数字和正文对不上，自己都说不清有多少题 | 结构校验脚本兜底，数量守恒算给你看 |

## 核心立场

这四条不是风格偏好，是整个 Skill 的硬边界。

**解析是唯一权威解源。** 它只做整理、归并、压缩、沉淀，不做题。不另起解法、不推翻解析结论、不「顺手纠正」解析。解析确实有错时，标注 `⚠` 报给你，不私自裁决。

**标注权在用户手里。** 错因 7 项、掌握度 3 档，一律输出未勾选的 `☐`。它只写「错因依据」作为判断线索——引用解析里的哪句话、哪个步骤暴露了问题——但不替你勾任何一项。

**编号一经生成永不改号。** 追加时先读旧文件，抽出现有模块 ID、各模块最大 Q/K 号、统计数字，新条目一律接在末尾往后排。不重排、不改写旧内容。

**数量守恒。** 输出题数 = 输入题数 − 重复合并数，front matter 的统计数字必须和正文实际数量一致。对不上就是校验失败，不是「大概差不多」。

## 产出长什么样

生成的错题本是一个固定骨架的 Markdown 文件，追加多少次都不会变形：

```
错题本/高中数学.md
├── YAML front matter         # 模块数 / 题数 / 知识点数 / 解析缺失数
├── 错题本变化信息             # 本次是首次生成还是追加，动了哪些编号
├── 目录                       # 带锚点的模块跳转，含题号区间
├── M01 函数与导数
│   ├── 知识点                 # [K-M01-01] 结论 | 识别特征 | 易错点 | 来源
│   └── 错题
│       └── Q-01 · 一句话说清错在哪
├── M02 数列
├── 通用方法索引               # 只在 ≥2 道题中出现的方法才进
├── M99 待归类                 # 挂不上模块的，写明卡在哪，不许丢
├── 重复项清单
├── 待人工确认                 # ⚠ 解析有问题的题号汇总
├── 解析缺失清单
└── 整理说明                   # 数量守恒算式，一眼能核对
```

每道错题是一张十一个字段的卡，长这样（完整示例见 [examples/高中数学.md](./examples/高中数学.md)）：

> **Q-07 · 含参讨论漏掉 a≤0 两种情况**
>
> - 考点：[K-M02-03]
> - 错因：☐ 概念不清　☐ 计算失误　☐ 审题偏差　☐ 思路断链　☐ 记忆混淆　☐ 时间不足　☐ 蒙对未掌握
> - 错因依据：解析第 2 段「需按 a>0、a=0、a<0 三种情况分别讨论」直接指出漏分类；我的答案默认 a>0，未讨论 a≤0
> - 一句话提醒：动笔前先写出 f'(x) 的判别式，按 Δ 的正负决定要不要分类
> - 掌握度：☐ 待复习　☐ 在练　☐ 已掌握

字段级的写法规范、七项错因的固定顺序、竖排可点击复选框变体，都在 [references/card-schema.md](./references/card-schema.md)。

## 安装

作为 Agent Skill 使用，把整个目录放进 skills 路径即可：

```bash
# 用户级（所有项目可用）
git clone https://github.com/chenxiao-reverie/cuotiben.git ~/.workbuddy/skills/cuotiben

# 项目级（仅当前项目可用）
git clone https://github.com/chenxiao-reverie/cuotiben.git .workbuddy/skills/cuotiben
```

目录里必须有 `SKILL.md`，加载时读它作为入口。

## 使用方式

不需要记命令，说人话就行：

| 你说 | 它做什么 |
|---|---|
| 贴一批带解析的错题 | 生成新错题本，按学科切模块 |
| 「又攒了一批，追加进去」 | 先读旧文件，接编号往后排，出追加补丁 |
| 「先看看模块怎么分」 | 只出模块地图，等你确认再出全文 |
| 「只要整理结果，别存文件」 | 仅在对话里输出，不落盘 |

多科混在一起发也没关系，它会一科一文件拆开（`错题本/高中数学.md`、`错题本/公考政治理论.md`），不会硬塞进同一个文件。

### 处理流程

```
贴入错题 + 解析
   ↓  拆条编号 Q-01… / K-01…，相似题合并
   ↓  定模块骨架（有章节标注用标注，否则按考纲切）
   ↓  写知识点（每条标来源：摘录 / 解析 / 推断）
   ↓  写错题卡（解析压缩 ≤5 步，错因全留空）
   ↓  组装落盘 + 变化信息段
   ↓  跑结构校验，报错就改到通过
交付
```

## 文件结构

```
cuotiben/
├── SKILL.md                    # 技能入口：核心立场 + 8 步工作流 + 硬性约束
├── references/
│   ├── taxonomy.md             # 模块切分规则 + 12 个学科的板块清单
│   ├── card-schema.md          # 错题卡 11 字段定义 + 错因枚举 + 完整示例
│   └── output-spec.md          # 输出骨架 + 各章节要求 + 追加补丁格式
├── scripts/
│   └── check_notebook.py       # 结构校验器
└── examples/
    └── 高中数学.md              # 通过校验的完整样例，可直接当模板改
```

| 文件 | 职责 | 何时被读取 |
|---|---|---|
| `SKILL.md` | 技能主文件，定义立场、流程、约束 | 技能加载时必读 |
| `references/taxonomy.md` | 模块数上限、命名规则、各学科板块清单 | 定模块骨架时 |
| `references/card-schema.md` | 字段表、枚举顺序、勾选框写法、常见错误对照 | 写错题卡时 |
| `references/output-spec.md` | 文件骨架、变化信息格式、统计口径 | 组装落盘时 |
| `scripts/check_notebook.py` | 8 项结构校验，退出码 0/1 | 每次落盘后 |

按需加载是刻意的设计：SKILL.md 只保留判断逻辑，细则摊到 references 里，避免一上来就把几千字灌进上下文。

## 输出规范速查

### front matter

| 字段 | 说明 |
|---|---|
| `title` | `错题本 · <学科>` |
| `updated` | `YYYY-MM-DD` |
| `modules` | 一级模块数，**不含 M99** |
| `questions` | 错题总数 |
| `points` | 知识点总数 |
| `parse_missing` | 解析缺失数 |

全部写纯数字，不写「约 10 个」——校验脚本要对它做算术。

### 错因枚举（固定 7 项，顺序不可调）

`概念不清` `计算失误` `审题偏差` `思路断链` `记忆混淆` `时间不足` `蒙对未掌握`

顺序固定是因为统计错因分布时要按位置对齐。不增删、不改名、不调序。

### 掌握度枚举（固定 3 档）

`待复习` `在练` `已掌握`

### 编号规则

| 类型 | 格式 | 例子 |
|---|---|---|
| 模块 | `M01`–`M16`，`M99` 固定为待归类 | `M03 立体几何` |
| 错题 | `Q-01`…，连续无跳号 | `Q-12` |
| 知识点 | `K-M<模块号>-<序号>` | `K-M05-03` |

知识点 ID 带模块号，所以错题的「考点」字段能直接反查到模块位置——这也是校验脚本会检查「引用的知识点是否有定义」的原因。

## 结构校验

写完必须跑，通过才算交付：

```bash
python3 scripts/check_notebook.py 错题本/高中数学.md
```

正常输出：

```
校验对象: 高中数学.md
  模块 2 / 错题 2 / 知识点 3 / 解析缺失 0

✓ 结构校验通过
```

出错时直接指到具体题号和字段：

```
校验对象: 高中数学.md
  模块 2 / 错题 2 / 知识点 3 / 解析缺失 0

✗ 发现 2 个错误:
  - Q-01 「错因」复选框应 7 个，实际 6 个
  - Q-02 「错因」复选框应 7 个，实际 6 个
```

覆盖八项：front matter 字段齐全且为数字、模块/题/知识点数与正文一致、Q 号连续无跳号无重复、每题必填字段齐全、复选框数量正确且无预勾选、考点引用有定义、七个必备章节存在、变化信息段存在。

退出码 `0` 通过（可能带警告），`1` 有错误，可以直接接进 CI 或 git hook。

## 可选开关

默认全关，你提到才开：

| 开关 | 触发方式 | 效果 |
|---|---|---|
| **补全模式** | 「解析缺的帮我补一下」 | 仅对解析缺失题补写，整段用 `>` 包裹并前置 `⚠ AI 补写，非原解析` |
| **大纲模式** | 「给我一份大纲，方便转思维导图」 | 额外输出 `模块 → 考点 → 题数 → 错因分布` 缩进大纲 |
| **可点击复选框** | 「预览里要能直接点」 | `☐` 单行改为 `- [ ]` 竖排，每题多 10 行，题量大慎用 |

补全模式有硬限制：原解析存在时，任何情况下都不许补写或改写。

## 支持的学科

内置 12 套板块模板，见 [references/taxonomy.md](./references/taxonomy.md)：

| 类别 | 学科 |
|---|---|
| 高中 | 数学、物理、化学、英语 |
| 公考 | 行测、申论、政治理论 |
| 职业资格 | 银行从业、教师资格证、法律职业资格 |
| 考研 / 财会 | 考研政治、CPA |

表里没有的学科也能用：它会翻原文里出现频率最高的方法名和概念名，聚成 3–8 组，并在「整理说明」里注明「本学科模块体系为按内容推断，非官方考纲」，你后面说「模块分得不对」就重排。

## 它不做什么

- ❌ 不替你做题。解析是唯一解源，不会另起一套解法
- ❌ 不猜错因。七项全留空，宁可整列显示「待标注」
- ❌ 不美化题干。原样照录，残缺处写 `[原文缺失: 缺什么]`，不自己补
- ❌ 不私自裁决解析错误。照抄原结论 + 标 `⚠` + 写疑点，全进「待人工确认」
- ❌ 不丢信息。合并的重复项、待归类条目、缺失字段，全部在末尾列出

**预期管理**：它产出的是「可复习的骨架」，不是「读完就能考高分」。错因要你自己勾，掌握度要你自己评，第二次追加时它会根据你勾的结果重算错因分布——这部分它不代劳。
